VLM·비전 모델이 현장에서 왜 실패하는지 찾아내고, 되게 만드는 엔지니어

오프라인에서 좋아 보이던 모델이 실제 환경에서 무너지는 지점을 측정으로 찾고, 프롬프트·입력·모델 선택·평가 기준을 바꿔 되돌립니다.

판정 기준을 먼저 세우고, 증명하지 못한 것을 함께 남기는 방식으로 일합니다.

이 기록이 지키는 것

  • 모든 수치에 측정 조건을 붙입니다. 조건이 빠진 숫자는 결과로 쓰지 않습니다.
  • 각 프로젝트의 마지막 항목은 증명하지 못한 것입니다.
  • 회사 프로젝트는 제품 아키텍처·내부 경로·고객 정보를 빼고 정리했습니다. 상세판은 요청하시면 보내드립니다.

8GB 엣지 디바이스에 2차 검증기를 올리기까지

8GB 공유 메모리에 2차 검증기를 추가할 수 있는지 판정한 기록. 입력을 줄여 1.8초를 300ms로 만들었고, 재현율은 끝내 측정하지 못했다.
2026.10 · 개인 프로젝트 · 공개 데이터 · 코드 공개
엣지 VLM 검증기를 2GB 안에 넣기: 양자화보다 런타임이 먼저였다

회사에서 남은 질문을 공개 데이터로 다시 풀었다. PyTorch FP16 2,810MB에서 llama.cpp Q8_0 1,755MB로, 낙상 AUROC는 낮아지지 않았다(0.960).
2026.10 · 개인 프로젝트 · 공개 데이터
VLM 검증기를 중앙 서버로 모으면: 처리량을 바꾼 것은 양자화가 아니라 배칭이었다

2차 검증을 GPU 서버 한 대로 모으면 카메라 몇 대까지 감당하나. 처리량은 배칭이 바꿨고(초당 25건 → 95건), AWQ는 바꾸지 못했다.
2026.02~05 · 회사 프로젝트 · 코드 비공개
설치 환경이 제각각인 카메라를 자동 재학습으로 따라가기

설치 환경이 제각각인 카메라를 자동 재학습으로 따라가는 파이프라인. 구조를 네 번 갈아엎었고, 개선 폭은 측정하기 전에 중단됐다.
